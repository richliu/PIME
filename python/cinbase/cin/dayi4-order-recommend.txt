dayi4.cin 候選字順序：我的處理建議
====================================================================================================
對應的調查表: dayi4-order-survey.txt
基準: dayi4.cin HEAD cd90061 / 2017 原始 45e19f0 / PR #1018 (asdf80730/PIME@83c7ecc dayi3.cin)

一、先釐清一件事：兩種模式對「好順序」的定義不同
----------------------------------------------------------------------------------------------------
1. 四碼模式 (dayi4.cin)
   每個字都有自己的完整碼。二碼、三碼鍵裡的「衍生字」(由四碼縮出來的) 本來就能用四碼直接打出來，
   不需要靠簡碼。反過來，「原生字」(完整碼就是這兩三碼) 只有這一個入口，排第二就得多按一次選字。
   所以四碼模式下，原生字優先是合理的預設；這也是 2005 年太易原表的做法。
   例外是太易自己在檔頭列的那批 (也道爸就像身假流遠應漢蘭動崗亂病碗獅據遊眾萬灣愈淨管舒陽制夢)：
   原生字極罕用、衍生字極常用，就把常用字提前。你 2019-2022 年改的那六十幾組，絕大多數也是這個邏輯。

2. 三碼模式 (dayi3.cin / dayi4-add3.cin 的三碼項)
   所有四碼字都被縮成三碼，原生三碼字和縮碼字變成同一個鍵下的平等候選，「原生」這個概念對打字的人
   不再有意義。這時候唯一合理的排序依據是使用頻率。Windows 大易三碼表 (PR #1018 對齊的對象)
   就是這個邏輯，所以它會出現 錯鈤、鐘釷、鄧鉺銵 這類「衍生字在前」的排法。

結論：PR 的順序是「三碼模式的好順序」，不等於「dayi4.cin 的好順序」。整批照抄到 dayi4.cin 會把
四碼模式的原生優先打壞。你覺得 Windows 版比較好，我同意一半：三碼模式應該跟它，四碼表要挑著用。

二、各類差異的處理方式
----------------------------------------------------------------------------------------------------
A. 與 PR 完全相同 (10665 鍵)：不動。

B. 只有字集不同 (PR 多了簡體字、粵語字、CJK 擴充字，附在尾端)：不動。
   dayi4.cin 是太易授權表，這些是 PIME 自己在 dayi3 加的產品層，不該回灌到 dayi4。
   PR 補回的十個字 (續縜絯．廘冢阱菶涪憶) dayi4 本來就有，也不用動。

C. 順序不同、你沒改過 (dayi4 2005 原表 vs Windows 表)：
   這是太易自己兩張表的分歧。以首字為準，因為大易自動上字只看第一個候選：
   - PR 首字是常用字、目前首字是次常用或 Big5 外：建議採 PR。原生字罕用到幾乎沒人打，提前常用字
     只有好處。這類大多是 錯鈤、鐘釷 之類。
   - 目前首字比 PR 首字常用：保留目前。
   - 兩者同級：保留目前，不要為了對齊而改。兩個都是常用字時，用「原生優先」當次要依據標成「傾向」，
     兩個都是原生或都是衍生的才真的留給你人工判斷。
   - 首字相同只有後面次序不同：保留目前，影響很小。

D. 順序不同、你改過：
   你改的方向 (把常用衍生字提前) 和太易 2005 檔頭的做法一致，也和 Windows 表大方向一致，
   只是 Windows 在部分鍵 (狺獅、仂像、茜蘭、栺楷、泍渣) 守住了原生優先。這些鍵的原生字都是
   次常用字，而你提前的字都是常用字，從四碼模式使用者的角度你的順序比 Windows 好，建議保留。
   唯一要回頭看的是「你改過、但 PR 首字反而比你的更常用」的鍵，逐鍵表裡會標出來 (本次結果是零筆)。

E. 四碼鍵本身的順序 (158 筆有差異)：四碼模式下同一個四碼有多字是重碼，跟 PR 三碼表沒有對應關係，
   這批不要用 PR 當依據，維持現狀。

三、工具面的建議
----------------------------------------------------------------------------------------------------
1. dayi4.cin 維持原生優先 + 常用字例外，當作唯一的手改來源。
2. dayi4to3.py 目前是把縮碼項附加在原生三碼項之後，等於自動做到原生優先，四碼模式沒問題。
3. 如果你也在用三碼模式，建議讓 dayi4to3.py 多讀一份「三碼順序覆蓋表」(可以直接用 PR 的 dayi3.cin)，
   產生 dayi3 時以它的順序重排同一鍵的候選字，這樣兩種模式各得其所，dayi4.cin 不必妥協。
4. Big5 常用/次常用分級只是頻率的粗略代理 (常用字 5401 字內部沒有排序)，表中標「人工判斷」的
   請用你自己的打字經驗決定。
